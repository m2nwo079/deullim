# UX 개선 목록

공통 컴포넌트 중심으로 일괄 리디자인할 때 다룰 문제를 모은다. 고치면 해당 행을 지우고 커밋 메시지에 남긴다.

| 화면 | 문제 | 관련 컴포넌트 | 메모 |
|---|---|---|---|
| 시연 QR 창의 단위작업 선택 (개선안 상세 → 시연 촬영) | 선택됨과 초점이 구분되지 않고, 글자 입력칸처럼 보인다 | SegmentedControl (web/src/components/choice-field.tsx) | 동그라미 표시 변형 검토. 동작은 이미 기본 라디오(fieldset, legend, 방향키)라 모양만 다룬다 |
| 견적 요청 상세 (초안) | 설명(1000자 이하)을 한 줄 입력칸에 적는다 | TextField | 여러 줄 입력 컴포넌트가 없다. 수시 조사 메모도 같다 |
| 견적 요청 상세 (초안) | 희망 기한 달력이 선택할 수 있는 마지막 날(2년 뒤)을 "오늘"로 표시하고(테두리, aria-current="date"), 값이 비어 있으면 달력이 2년 뒤 달에서 열린다. 입력 예시도 그 날짜다 | DateField (web/src/components/date-field.tsx) | 표시만의 문제다. 값은 "YYYY-MM-DD" 문자열로만 다루고 Date 시간대 변환을 거치지 않아 저장 날짜는 어긋나지 않는다. max를 오늘로 가정한 컴포넌트라, 미래 날짜용으로 today와 max를 나누는 변형 검토 |
| 견적 요청 상세 (초안) | "저장"과 "공개하기"가 따로 있어, 저장하지 않고 공개하면 고친 내용이 빠진다 | Button, Modal | 공개 확인 창에 "저장된 내용이" 공개된다고만 적었다. 공개 전에 저장을 함께 하는 흐름 검토 |
| 개선안 상세의 개선안 표 | 관리 열의 버튼이 수정, 시연 촬영, 견적 요청(요청 보기), 삭제 4개로 늘었다 | DataTable | 더보기 메뉴나 행 상세로 모으는 방법 검토 |
| 개선 계획 | 새로 계산한 결과를 저장된 계획과 견주려면 저장된 계획 화면을 따로 열어야 한다 | DataTable, 개선 계획 화면 | 시연 3단계(수락 뒤 1,000만 원 다시 계산)에서 드러난다. 저장된 계획 하나를 골라 나란히 보여 주는 방법 검토 |
