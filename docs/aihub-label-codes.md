# AI Hub 라벨 코드 역추정 결과

## 출처와 이용 표시
- 데이터: AI Hub "제조업 노동자 근골격계 부담요인 예방을 위한 인공지능 데이터 구축" (dataSetSn 71439)
- 본 문서의 분석은 한국지능정보사회진흥원의 「지능정보산업 인프라 조성」 사업 결과물인 위 데이터를 이용했다.
- 원본 데이터와 개별 레코드는 이 문서에 포함하지 않는다. 집계 수치만 적는다.

## 문서의 성격
- 아래 "코드 의미"는 정답 키포인트로 계산한 2D 관절 각도의 분포로부터 역추정한 가설이다.
  데이터 구축기관의 공식 정의가 아니다. 공식 답변을 받으면 이 문서를 갱신한다.
- 분석 코드: analysis/aihub_label_inference/
- 결과 파일(로컬 전용, 커밋하지 않음): analysis/aihub_label_inference/results/
  - posture_code_angles_v1~v4.md (Validation), posture_code_angles_v4_training.md (Training)
- 분석 범위: Validation 라벨 12,000건, Training 라벨 96,000건. 이미지는 사용하지 않았다.

## 2. posture 코드 의미 (역추정)
각도는 2D 이미지 평면 기준이며, 수치는 Training 사업장 5곳의 중앙값 범위다.

### trunk (허리) — 신뢰도 높음
| 코드 | 몸통 기울기 중앙값 | 추정 의미 |
|---|---|---|
| 0 | 4~8도 | 바로 선 자세 |
| 1 | 33~46도 | 앞으로 숙인 자세 |
- 두 코드 분포의 교차점은 사업장마다 2D 기준 약 25~30도.

### upperarm (위팔) — 신뢰도 높음 (코드 2 제외)
| 코드 | 위팔 각도(좌우 중 큰 값) 중앙값 | 추정 의미 |
|---|---|---|
| 1 | 12~17도 | 팔을 내린 상태 |
| 0 | 34~48도 | 약 20~90도로 든 상태 |
| 3 | 102~129도 | 어깨 높이 이상으로 든 상태 (주로 한쪽) |
| 2 | 45~50도 (사업장별 11~37건) | 미확인. 뒤로 젖힘일 가능성 |
- 코드 번호 순서와 각도 순서가 일치하지 않는다.
- 1과 0의 경계는 약 20도로 뚜렷하고, 0과 3은 90~120도 구간에서 겹친다.
- 현재 각도는 앞뒤 방향을 구분하지 않으므로 코드 2의 의미는 확인되지 않았다.

### neck (목) — 신뢰도 중간
| 코드 | 목 숙임 중앙값 | 추정 의미 |
|---|---|---|
| 0 | 6~9도 | 거의 숙이지 않음 |
| 1 | 14~20도 | 약간 숙임 |
| 2 | 25~38도 | 많이 숙임 |
- 코드 0과 1의 분포가 크게 겹쳐 경계 각도를 특정하지 못했다.
- 코드 1과 2의 교차점은 2D 기준 약 25~35도.
- "코드 0 = 뒤로 젖힘" 가설은 기각 (VL에서 젖힘 방향 비율 20.1%).

### legs (다리) — 코드별로 다름
| 코드 | 특징 | 추정 의미 | 신뢰도 |
|---|---|---|---|
| 1 | 무릎 굽힘 6~10도, 엉덩이 굽힘 작음 | 두 다리를 펴고 선 자세 | 높음 |
| 0 | 무릎 굽힘 120~150도, 무릎이 발목 가까이 내려옴 | 쪼그려 앉거나 낮게 앉은 자세 | 중간 |
| 5 | 무릎 깊게 굽음, 무릎이 발목보다 아래 (F05 516건) | 무릎 꿇은 자세 | 중간~높음 |
| 3 | 양쪽 무릎 중간 정도 굽음 | 두 다리를 구부린 자세 | 중간 |
| 2 | 드묾, 한쪽만 굽고 발목 높이 차가 큼 | 한 다리로 선 자세 | 낮음 |
| 4 | 사업장마다 분포가 다름 | 미확인 | 낮음 |
- 구조는 OWAS 다리 분류와 유사하다 (가이드라인 43쪽 선택지, 51쪽 "다리 6개").
- legs_supported=1인 레코드의 무릎 굽힘 중앙값(121.6도, VL)이 코드 0과 같다.

### lowerarm (아래팔) — 신뢰도 낮음, 검증에 사용하지 않음
- 팔꿈치 굽힘 각도로는 코드가 구분되지 않는다.
- 손이 어깨보다 위에 있는지와 관련이 있어 보이나, 사업장마다 양상이 다르다.
  - F02: 코드 1의 84%가 한 손이 어깨 위
  - F04: 코드 2의 77%가 두 손 모두 어깨 아래

## 3. 부가정보 플래그
- 대부분 1이 "유"로 해석된다 (예: upperarm_abduction=1의 위팔 각도 중앙값 98.2도, 0은 38.6도, VL).
- 다음 세 플래그는 값이 거의 한쪽으로 몰려 있어 신뢰하지 않는다 (VL 기준).
  - neck_twist: 12,000건 중 11,997건이 1
  - wrist_twisted: 10,407건이 1
  - upperarm_raised: 전부 0
- neck_bending, trunk_bending은 가이드라인상 "옆으로 굽힘"이나 앞으로 숙인 각도와 강하게 연관된다.
  2D 투영의 영향인지 라벨링 기준 차이인지 확인되지 않았다.

## 4. 키포인트 flag 1, 2
- 의미 미확인. COCO 형식(1 가려짐, 2 보임)과 맞지 않는다.
  - 상반신 이미지에서 화면 밖에 임의로 찍은 무릎의 87%가 flag 2
  - 픽셀 처리된 코(3번)는 77%가 flag 1, 직접 보이지 않는 척추(17번)는 87%가 flag 2
- 검증의 필터로 사용하지 않는다.

## 5. 들림 검증에 주는 의미
| 항목 | 검증에 사용할 경계 | 신뢰도 |
|---|---|---|
| 허리 | 바로 섬 / 숙임 | 높음 |
| 위팔 | 내림 / 약 20~90도 / 90도 이상 | 높음 |
| 목 | 많이 숙임(코드 2) 여부 | 중간 |
| 다리 | 선 자세 / 무릎 굽힘 / 무릎 꿇음 | 중간 |
| 아래팔 | 사용하지 않음 | 낮음 |
- 라벨 체계는 REBA 부위별 점수와 일치하지 않고 OWAS, RULA 분류가 섞인 형태로 보인다.
  REBA 판정 결과를 그대로 대조하지 않고, 대응되는 경계만 대조한다.
- 라벨러가 20도 기준으로 판단했을 것으로 보이는 경계가 2D 이미지 평면에서는 약 25~30도에서 나타난다.
  2D 측정값에 REBA 기준을 그대로 적용하면 사람의 판단과 체계적인 차이가 생길 수 있다.
- Validation은 사업장 1곳이며, 카메라 구도가 공정과 얽혀 있다 (예: F01_P007은 구도 1로만 촬영).
  구도별 정확도 분석 시 이 한계를 함께 밝힌다.
- 향한 쪽 판단 기준이 서비스와 다르다. 이 분석은 코와 몸통선 사이 거리가 몸통 길이의 0.05 이상일 때 방향을 정했고
  (analysis/aihub_label_inference/infer_posture_codes.py의 FACING_MIN_RATIO), 서비스는 발 방향을 먼저 쓰고
  발로 정할 수 없을 때만 코 기준 FACING_MIN_OFFSET 0.1(시작값)을 쓴다.
  검증 결과를 비교할 때 이 차이를 함께 밝힌다.

## 6. 미해결 질문 (데이터 구축기관 문의 대상)
- posture 각 항목의 코드별 공식 정의
- 부가정보 플래그 값의 의미와, 값이 한쪽으로 몰린 플래그의 원인
- 키포인트 flag 0, 1, 2의 의미
- bbox 형식과 키포인트 배열 순서의 공식 확인
- 비공개 12,000건의 성격과 공개 계획
- light 값의 정의
- 검증 용도와 2D 기준값 보정이 이용정책의 "학습용" 범위에 해당하는지
