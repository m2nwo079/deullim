# 개선 투자 최적화 모델 (v1, solver_version: mckp-dp-v1)

## 문제
한정된 예산 안에서 공정별 개선안을 하나씩 골라(또는 고르지 않고), 하루 고위험 자세 노출을 가장 많이 줄인다.
다중 선택 배낭 문제(Multiple-Choice Knapsack Problem)로 정식화하고, TypeScript 동적계획법으로 정확한 최적해를 구한다. 외부 솔버는 쓰지 않는다.

## 기호
| 기호 | 의미 | 출처 |
|---|---|---|
| i | 공정 (workstation) | |
| t | 공정 i의 단위작업 (task) | |
| j | 공정 i의 개선안 (improvement_option). j = 0은 "개선하지 않음" | |
| n_i | 공정 인원 | workstations.headcount |
| h_t | 단위작업의 하루 작업 시간 (시간) | 관리자 입력 |
| r_t | 현재 고위험 비율 | 최신 assessments.high_risk_ratio |
| r'_tj | 개선안 j 적용 후 예상 고위험 비율 | 개선 시뮬레이션 결과 또는 관리자 입력 |
| c_ij | 개선안 비용 (원) | improvement_options.cost 또는 견적 |
| B | 예산 (원) | 관리자 입력 |

## 위험 감소량 (결정: B안, 노출 시간 반영)
v_ij = n_i × Σ_t h_t × (r_t − r'_tj)

- 단위는 "하루 고위험 노출 사람·시간"이다. 예: 5명이 하루 4시간 하는 작업의 고위험 비율이 40%에서 10%로 줄면 5 × 4 × 0.3 = 6 사람·시간/일.
- v_i0 = 0, c_i0 = 0
- 개선안이 영향을 주지 않는 단위작업은 r'_tj = r_t로 둔다.

## 입력 처리
- 감소량이 0 이하인 개선안(v_ij ≤ 0)은 후보에서 뺀다. 계획 결과에 따로 표시하지 않는다.
- 한 개선안이 여러 단위작업에 효과를 주면 위 식대로 모두 더한다. 어떤 단위작업이 나빠지는(r'_tj > r_t) 효과도 그대로 더해 상쇄한다.
- 평가가 없는 단위작업(r_t 없음)은 효과가 있어도 0으로 계산하고 경고하지 않는다.
  콘솔의 하루 고위험 노출이 평가되지 않은 단위작업을 빼는 것과 같은 기준이다 (docs/console-metrics.md).
- 효과는 개선안과 같은 공정의 단위작업에만 둘 수 있다 (DB 트리거, docs/data-model.md).
- r'_tj는 단위작업마다 하나다. 시연 촬영(simulation)이 있으면 그 촬영의 high_risk_ratio를 그대로 쓰고, 없으면 관리자 입력(manual)을 쓴다. 변환이나 보정은 하지 않는다.
  시연 촬영도 단위작업에 저장된 관리자 입력(하중, 손잡이 등)으로 채점하므로 자세 변화만 반영되고 조건 변화는 반영되지 않는다.
- 시연 촬영 값이 현재보다 높으면(r'_tj ≥ r_t) 그 효과도 그대로 저장한다. 위 규칙대로 감소량에 0 이하로 더해져, 개선안 전체가 0 이하면 후보에서 빠진다.

## 정식화
최대화 Σ_i Σ_j v_ij · x_ij

제약
- Σ_i Σ_j c_ij · x_ij ≤ B
- 각 공정 i에 대해 Σ_j x_ij = 1 (j = 0 포함)
- x_ij ∈ {0, 1}

## 풀이
1. 비용을 COST_UNIT(1만 원) 단위로 올림하고, 예산은 COST_UNIT 단위로 내림해 정수로 바꾼다.
   올림·내림이므로 실제 비용 합은 예산을 넘지 않는다.
   - 처음에는 10만 원 단위였으나 1만 원으로 바꿨다. 10만 원 단위로 올림하면 실제 비용이 예산에 딱 맞는
     조합을 놓친다. 예: 15만 원 + 25만 원 = 40만 원인데 2 + 3 = 5단위가 되어 예산 40만 원(4단위)에 들어가지 않는다
     (tests/fixtures/mckp_example_v1.json).
   - 1만 원 단위에서도 1만 원 미만 끝자리가 있는 비용은 올림 때문에 같은 문제가 남는다.
     예: 비용 123,400원은 13단위, 예산 123,400원은 12단위라 들어가지 않는다.
2. 공정마다 v_ij ≤ 0인 개선안과, 같은 공정 안에서 비용이 더 크면서 감소량이 크지 않은 개선안(지배당한 안)을 제거한다.
3. dp[k][b] = 처음 k개 공정까지 고려하고 예산 단위 b 이하를 썼을 때의 최대 감소량. 공정마다 j = 0을 포함해 갱신한다.
4. 역추적으로 공정별 선택을 복원한다.
5. 감소량이 같으면 비용이 작은 해, 그다음 선택한 개선안 수가 적은 해를 고른다.

- 예산 상한: 10억 원 (100,000단위). 넘으면 예외를 낸다.
- 계산량: O(Σ_i m_i × B / COST_UNIT). m_i는 공정 i의 개선안 수.
  공정 50개 × 개선안 5개일 때, 예산 1억 원(10,000단위)이면 약 250만 번, 상한 10억 원(100,000단위)이면 약 2,500만 번 갱신한다.
  역추적용 선택 기록은 공정 수 × (예산 단위 + 1)칸으로, 상한에서 약 500만 칸이다 (어림 계산, 실측 아님).

## 출력
| 출력 | 내용 |
|---|---|
| plan | 공정별 선택 개선안, 비용, 감소량 |
| total_cost, total_reduction | 합계 |
| budget_curve | 0원부터 입력 예산까지 CURVE_STEP(10만 원)마다의 최대 감소량. dp의 마지막 행에서 해당 지점의 값을 뽑는다. 입력 예산이 CURVE_STEP으로 나누어떨어지지 않으면 입력 예산을 마지막 점으로 하나 더 넣어, 곡선의 끝이 계획의 총 감소량과 같게 한다 |
| warnings | 아래 경고 목록 |

- budget_curve는 "예산을 더 쓰면 노출이 얼마나 더 줄어드는가"를 보여주는 그래프로 콘솔에 표시한다.

## 경고
- 최신 평가의 위험도 단계가 "매우 높음"인 공정이 계획에서 선택되지 않으면 경고한다. 인원이 적어 감소량이 작게 계산되는 공정이 밀리는 문제를 관리자가 판단하도록 하기 위해서다.
- 개선 후 예상값이 관리자 입력인 개선안은 "예상값 근거: 관리자 입력"으로 표시한다.
  관리자 입력이 하나도 없는 개선안은 "시연 촬영값"으로 표시한다. 계획에 들어간 개선안은 감소량이 0보다 커서 효과가 하나 이상 있으므로, 관리자 입력이 없으면 모두 시연 촬영이다.
- 평가 결과가 오래된 공정(기준 TBD)은 재촬영을 권한다.

## 테스트
- 합성 데이터로 작은 문제를 무작위 생성해, 모든 조합을 전부 따져 본 결과와 DP 결과가 같은지 확인한다.
- 예산 0, 개선안 없음, 모든 개선안이 예산 초과, 비용이 단위의 경계에 걸리는 경우를 포함한다.
- 실제 사업장 데이터나 AI Hub 데이터는 테스트에 쓰지 않는다.

## 한계 (MVP)
- 개선안 사이의 상호작용(같은 공정의 여러 개선 동시 적용)은 다루지 않는다. 공정당 하나만 고른다.
- 공사 기간, 동시 공사 수, 여러 해에 걸친 예산은 다루지 않는다.
- 개선 후 예상값의 정확도에 결과가 크게 의존한다.
