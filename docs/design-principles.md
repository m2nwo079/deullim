# 들림 디자인 원칙 (v1)

토큰(docs/design-tokens.md)과 컴포넌트(docs/components.md)는 이 원칙을 따른다. 원칙과 토큰이 충돌하면 원칙을 기준으로 토큰을 고친다.

## 방향
- 깔끔하고 전문적인 B2B SaaS 콘솔의 구성(왼쪽 내비게이션, 흰 내용 영역, 얇은 구분선, 표 중심)을 바탕으로 한다.
- 그 위에 제조 현장과 산업안전의 규칙(산업 제어 화면 표준, 안전보건표지, 점검표 서식)을 얹어 들림만의 성격을 만든다.

## 원칙
| 번호 | 원칙 | 근거 | 화면에서의 의미 |
|---|---|---|---|
| P1 | 화면은 조용하게, 색은 사건에만 | ISA-101 고성능 HMI (회색 바탕, 비정상 상태에만 색) | 화면 대부분은 흰색과 중립 회색. 관리자 콘솔에서 위험도 색은 "높음" 이상에만 쓴다 |
| P2 | 주 색은 지시에만 | 산업안전보건법 시행규칙 별표 8 (파란색: 특정 행위의 지시) | 브랜드 색은 사용자에게 행동을 요구하는 요소에만 쓴다. 장식이나 알림 배경에 쓰지 않는다 |
| P3 | 서식처럼 정렬 | 현장 점검표, 공공 서식 패턴 | 같은 카드를 반복하지 않는다. 표와 구획선으로 정리한다 |
| P4 | 표지처럼 읽히게 | 안전환경디자인 매뉴얼의 안전사인 유형 | 위험도는 굵은 색 막대와 글자 라벨로 표시한다. 파스텔 배경의 둥근 배지를 쓰지 않는다 |
| P5 | 한 화면에 강조는 하나 | 디자인 스킬의 절제 원칙 | 화면마다 가장 중요한 수치나 동작 하나만 크게 둔다 |
| P6 | 현장의 언어 | 소재 | 공정명, 작업대 번호처럼 실제 이름을 쓴다. 견본 문구를 쓰지 않는다 |

### 문구 규칙 (P6 현장의 언어)
- 가운뎃점(·)으로 낱말을 나눌 때는 양옆을 한 칸씩 띄운다. 버튼, 라벨, 단위, 칩, 제목 등 화면에 보이는 모든 문구에 적용한다.
  예: "사람·시간" → "사람 · 시간", "손·손목·손가락" → "손 · 손목 · 손가락"
- 문장형 안내(서술어로 끝나는 문장)는 마침표를 찍는다. 버튼, 라벨, 제목, 탭은 찍지 않는다.
  예: "이름은 남지 않아요" → "이름은 남지 않아요.", 버튼 "신고 보내기"는 그대로
  제목은 문장 모양이어도 찍지 않는다 (예: 빈 상태 제목 '이번 주에 들어온 신고가 없어요')

## 화면별 적용
### 관리자 콘솔, 파트너 페이지
- 배경: 내용 영역은 흰색, 내비게이션과 페이지 바탕은 gray-50
- 요약 수치는 카드 여러 장이 아니라 하나의 테두리 안에서 세로선으로 나눈다
- 공정 목록, 신고 집계, 개선 계획은 표로 둔다. 숫자는 고정폭, 오른쪽 정렬
- 위험도 색: "높음", "매우 높음"만 색 막대와 색 글자. "주의", "낮음"은 중립 회색 막대와 회색 글자
- 기한, 안내, 오류 알림은 위험도 색을 쓰지 않는다. 중립 배경과 아이콘, 글자로 표시한다
- 주 버튼은 화면당 하나. 나머지는 보조 버튼

### 작업자 화면
- 화면마다 핵심 숫자 하나(예: 오늘 자세 부담 점수)를 display 크기로 둔다
- 개인 결과는 값이 하나뿐이라 묻힐 위험이 없으므로 네 단계 모두 위험도 색을 쓴다
- 부위별 내역은 카드가 아니라 구분선으로 나눈 행으로 둔다
- 카드는 "들려요" 공감 카드 하나만 쓴다. 공감의 순간이 화면에서 유일하게 다른 모양으로 드러나게 한다
- 터치 영역은 최소 48px. 핵심 동작 버튼은 화면당 하나, 하단에 둔다
- 선별 결과라는 안내 문구("정밀 조사를 대신하지 않는 선별 결과예요")를 결과 화면에 둔다

## 피하는 것
- 따뜻한 크림색 배경
- 같은 모양의 둥근 카드 반복, 모든 요소에 같은 그림자
- 파스텔 배경의 알약형 배지
- 제목 위의 작은 대문자 라벨, 장식용 그라데이션, 반복되는 장식 모션
- 맥락 없는 견본 문구
