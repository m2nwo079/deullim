# 들림 공통 컴포넌트 (초안 v1)

원칙은 docs/design-principles.md, 토큰은 docs/design-tokens.md를 따른다. 이 문서는 컴포넌트의 종류, 크기, 상태, 사용 규칙을 정한다.

## 원칙
- 화면 코드에서는 이 문서의 공통 컴포넌트를 쓴다. 긴 Tailwind 클래스 나열은 공통 컴포넌트 안에만 둔다.
- 컴포넌트 안에서도 의미 토큰과 컴포넌트 토큰만 쓴다. hex 값과 Tailwind 기본 색은 쓰지 않는다.
- 위험도 색은 RiskBadge, RiskBar, HeatmapCell에서만 쓴다.
- 새 공통 컴포넌트가 필요하면 임의로 만들지 않고 사용자에게 묻는다.

## 크기
| 화면 | 컨트롤 높이 | 비고 |
|---|---|---|
| 관리자 콘솔, 파트너 페이지 | 40px | |
| 작업자 화면 | 최소 48px | 장갑 착용 고려 |
| 작업자 화면의 핵심 동작 (촬영 시작, 신고 보내기) | 56px | 화면당 하나 |

- 모서리: 컨트롤은 radius-control(8px), 카드와 패널은 radius-surface(12px), 모달과 하단 시트는 radius-surface-lg(16px)

## 간격
세로 간격은 docs/design-tokens.md의 8px 배수만 쓴다. 한 묶음 안의 간격은 묶음 사이 간격의 절반 이하로 두어, 제목과 라벨이 아래 내용에 붙어 보이게 한다.

| 관계 | 콘솔·파트너 | 작업자·시연 |
|---|---|---|
| 라벨 → 입력칸·선택지 | 8px | 16px (라벨이 title-sm) |
| 입력칸 → 오류·도움말, 도움말끼리 | 8px | 8px |
| 입력 묶음 → 다음 입력 묶음 | 24px | 32px |
| Breadcrumb → 제목, 제목 → 제목 아래 설명 | 8px | 8px |
| 화면 제목 묶음 → 첫 내용 | 32px | 32px |
| 소제목(h2) → 그 내용 | 16px | 16px |
| 절과 절 사이 | 48px. 구분선을 두면 선 위아래 각 24px | 32px |
| 버튼 줄의 위쪽 | 마지막 입력 묶음과 32px. 폼 전체 오류(InlineAlert)는 버튼 줄 바로 위 16px. Modal 안에서는 본문과 24px | 32px. 핵심 버튼은 화면 맨 아래 |
| 화면 바닥 | 내용 끝에서 64px 뒤에 PageFooter | max(24px, env(safe-area-inset-bottom)), 푸터 없음 |

- fieldset의 legend는 flex 배치에 들어가지 않으므로 gap 대신 legend와 설명 문구의 아래 여백으로 띄운다.
- PageFooter: 진입 화면, 로그인 화면, 콘솔·파트너 레이아웃 맨 아래. 위 구분선, 안쪽 위아래 24px, caption 글자, text-secondary. 내용이 짧아도 화면 맨 아래에 둔다. 첫 줄에 진입 화면 `/`로 가는 "들림"과 `/privacy`로 가는 "개인정보와 촬영 안내" 링크를 나란히 둔다(작은 글자 링크: hover와 키보드 초점에서 밑줄, focus-ring). 작업자·시연 화면에는 이 링크를 두지 않는다(같은 탭에서 떠나면 QR 정보가 사라진다). 그 아래 안내 문구("들림의 결과는 정밀 조사가 필요한 공정을 고르기 위한 참고 자료예요. 최종 유해요인조사와 근로자 참여는 사업장에서 진행해요.")를 두고, 공모전 문구는 page-footer.tsx의 상수에 값이 있을 때만 그 아래에 그린다. 실제 연락처와 이메일은 넣지 않는다. 인쇄할 때는 숨긴다.
- 작업자·시연 화면(/w, /s)은 푸터를 두지 않는다. 바닥 여백의 env(safe-area-inset-bottom)은 viewport-fit=cover가 아닐 때 0이라 지금은 24px이다.

## 상태
모든 컨트롤은 아래 여섯 상태를 정의한다.

| 상태 | 표현 |
|---|---|
| 기본 | 컴포넌트별 정의 |
| hover | 한 단계 진한 토큰 (예: primary → primary-hover), motion-fast |
| 누름 | 두 단계 진한 토큰 (예: primary-active) |
| 키보드 포커스 | focus-ring 색 2px 테두리, 2px 간격 |
| 비활성 | surface-sunken 배경, text-disabled 글자, 포인터 비활성 |
| 로딩 | 라벨 자리에 진행 표시, 크기 유지, 중복 입력 차단 |

## 목록
| 분류 | 컴포넌트 | 규칙 |
|---|---|---|
| 기본 | Button | 종류: primary, secondary, text. 화면당 primary는 하나. 위계는 아래 "버튼 위계"를 따른다. 다른 화면으로 가는 것은 Button 모양이 아니라 TextLink로 둔다. 예외는 진입 화면 `/`의 로그인 버튼 하나뿐이다(ButtonLink primary). text(글자 모양 버튼)는 그 자리에서 창을 열거나 동작하는 것(예: "시연 촬영", QR "기간 연장")에만 쓰고, 이동이 아니라는 단서로 아이콘을 함께 둔다 |
| 기본 | TextLink | 다른 화면으로 가는 글자 링크(이동 전용). 그 자리에서 창을 열거나 동작하는 것은 Button text로 둔다. 필요하면 화살표 아이콘을 붙인다. 밑줄은 hover와 포커스에서 보인다. 행 전체 링크 표에서는 stretched로 누름 영역을 행 전체로 늘린다 |
| 기본 | Select | 하나를 골라 바로 화면이 바뀌는 선택(사업장, 보고서에 넣을 계획). 라벨을 항상 보이게 둔다. 운영체제마다 모양이 다른 네이티브 select 대신 WAI-ARIA APG 선택 전용 콤보박스로 직접 그린다: 포커스는 버튼에 두고, 방향키·Home/End·글자 입력으로 찾고, Enter·Space로 열고 고르며, Esc는 값을 바꾸지 않고 닫는다. 고른 항목은 체크 표시와 aria-selected. 연 채로 스크롤하거나 바깥을 누르면 닫힌다. 폼 안에서는 숨은 input으로 값을 보낸다. 머리글처럼 한 줄에 놓일 때는 라벨을 선택 상자 왼쪽에 둔다(labelPosition="side", 보이는 라벨 그대로) |
| 기본 | TextArea | 100자를 넘게 받는 입력. 글자 수 한도를 라벨에 적는다. 나머지 규칙은 TextField와 같다 |
| 기본 | IconButton | 아이콘만 있을 때도 접근성 이름(aria-label)을 반드시 둔다 |
| 기본 | DateField | 콘솔 날짜 입력. 마우스 화면에서는 직접 입력(2026. 10. 14., 2026-10-14 등)과 들림 달력을 함께 둔다. 달력은 WAI-ARIA APG 날짜 선택 대화상자 방식으로, 입력 칸 아래에 펼친다: 화살표(하루·한 주), Home/End(주의 처음·끝), PageUp/PageDown(한 달), Shift+PageUp/PageDown(한 해), Enter·Space(고르기), Esc(닫고 달력 버튼으로 돌아가기). 날짜는 "2026년 10월 14일 수요일"로 읽고, 오늘은 aria-current="date", 고를 수 없는 날은 aria-disabled. 주는 일요일부터. max(오늘) 이후와 min 이전은 고를 수 없고 초점도 그 밖으로 가지 않는다. Modal 안에서 Esc는 달력만 닫는다. 터치 화면(pointer: coarse)에서는 기기의 기본 날짜 입력을 쓴다. 제출 값은 "YYYY-MM-DD" |
| 기본 | MoneyField | 원 단위 금액 입력. 입력하는 동안 천 단위 쉼표를 붙이고 커서 위치를 숫자 기준으로 유지한다. 숫자 키패드(inputMode="numeric"). 서버에는 쉼표를 뺀 숫자만 보낸다. 나머지 규칙은 TextField와 같다 |
| 기본 | TextField, Select, Checkbox, Toggle, SegmentedControl, Tabs | 라벨은 항상 보이게 둔다. placeholder를 라벨 대신 쓰지 않는다. 입력 오류는 브라우저 말풍선 대신 칸 아래 문구로 알리고, aria-invalid와 aria-describedby로 칸에 연결하며, 칸 테두리를 border-text로 바꾼다. 폼 전체에 대한 오류(저장 실패, 중복 등)는 제출 버튼 바로 위에 InlineAlert error(role="alert")로 둔다. 폼 안의 항목 사이는 24px, 한 항목의 라벨·입력·오류·안내 사이는 8px로 둔다. SegmentedControl은 칸 없는 라디오 목록이다. 작업자 크기(worker, 줄 높이 48px 이상)와 콘솔 크기(console, 40px 이상, TextField와 같은 라벨)가 있고, 배치는 가로(horizontal, 선택지 사이 32px), 한 줄에 하나(vertical, 긴 문장, 줄 사이 8px), 여러 열(grid, 짧은 이름 여러 개, 열 사이 32px)이다 |
| 피드백 | Toast | motion-base로 나타나고 4초 후 사라진다 (시작값). 중요한 결과는 Toast만으로 알리지 않는다 |
| 피드백 | InlineAlert | 위험도 색을 쓰지 않고 중립 배경과 아이콘으로 표시한다. 종류(tone): 일반(info, info 아이콘), 주의(caution, alert 아이콘), 기한(deadline, clock 아이콘), 오류(error). 시계 아이콘은 기한에만 쓴다. 오류는 왼쪽 3px 막대와 굵은 글자, alert 아이콘을 모두 text 색으로 표시하고 role="alert"로 바로 알린다. 그 밖의 아이콘(lock 등)은 icon으로 따로 지정한다 |
| 피드백 | EmpathyCard | "들려요" 응답 전용. empathy-bg, empathy-fg, 대표 모션 |
| 피드백 | EmptyState, Skeleton, ProgressIndicator | 빈 화면 안내는 공감 톤의 문구를 쓴다 |
| 데이터 | RiskBadge | 표지형: 왼쪽 3px 색 막대 + 라벨 글자. 배경 없음, 모서리 없음. 콘솔에서 낮음·주의는 중립 회색 |
| 데이터 | RiskBar | 색 막대와 함께 수치 또는 라벨을 표시한다 |
| 데이터 | HeatmapCell | 칸마다 위험 단계 숫자나 짧은 라벨을 표시한다. 색으로만 구분하지 않는다. 콘솔에서는 높음 이상만 색 |
| 데이터 | Sparkline | 작은 추이 선 그래프. 기본은 중립 회색, 콘솔에서는 높음 이상만 위험도 색. 여러 행은 같은 눈금(0~100%)으로 그린다 |
| 데이터 | DataTable, StatStrip | 숫자는 고정폭, 오른쪽 정렬. 동작 열(버튼)은 내용 폭만 차지하고 표 오른쪽 끝에 붙인다(action 열). 행 하나를 고르는 표는 선택 열(radio)을 왼쪽 끝에 둔다(아래 "선택 요소"). 요약 수치는 카드 여러 장 대신 하나의 테두리 안에서 세로선으로 나눈다 (StatStrip). 두 값의 차이는 화면에 보이는 반올림 값끼리 빼서, 옆의 "34.5 → 37.1"과 늘 맞게 한다. 보이는 값이 같은데 실제로는 다르면 "0.1 미만 증가", "0.1 미만 감소"로 적고 단위를 붙이지 않는다(개선 계획 비교) |
| 덮는 요소 | Modal | 관리자 콘솔용. 표면 3층. 네이티브 dialog(showModal)로 포커스를 안에 가두고, Esc로 닫으며, 닫으면 연 요소로 포커스를 돌려준다. 버튼은 취소를 먼저 둔다. 창의 폭은 min(480px, 화면 폭 − 32px)이다. 본문은 한글 띄어쓰기 단위로 줄바꿈하고, 한 단어가 창보다 길 때만 단어 중간에서 끊는다. 창 안에 가로 스크롤을 만들지 않는다 |
| 덮는 요소 | BottomSheet | 작업자 화면용. 표면 3층 |
| 덮는 요소 | Popover | 표면 2층. 표의 행 "더보기" 메뉴(IconButton more로 연다)에 쓴다. 항목은 PopoverItem(동작은 버튼, 이동은 링크), 위험 동작 앞에는 PopoverDivider를 둔다. Esc, 바깥 누름, 화면 스크롤, 항목 선택으로 닫고, 닫으면 연 버튼으로 포커스를 돌려준다. 항목이 여는 확인 창은 메뉴 밖에 둔다(메뉴가 닫히면 그 안의 내용도 보이지 않는다) |
| 내비게이션 | ConsoleSidebar | nav 토큰. 콘솔 1단계 화면 사이를 오간다. 넓은 화면에서는 왼쪽 고정, 좁은 화면에서는 서랍(아래 "이동") |
| 내비게이션 | Breadcrumb | 2단계 이하 화면의 제목 위에 지금까지의 경로 전체를 보여 준다. 마지막 항목은 지금 화면이라 링크가 아니다 |
| 내비게이션 | PageHeader | 콘솔·파트너 화면의 제목 묶음: Breadcrumb(2단계 이하), 제목, 제목 아래 정보(인원처럼 경로가 아닌 것), 오른쪽 동작, 이동 뒤 결과 알림(?done=). 아래 첫 내용과 32px, 화면의 다른 묶음 사이는 48px("간격") |
| 내비게이션 | PageFooter | 콘솔·파트너 화면의 바닥. 위 "간격" 절을 따른다 |
| 내비게이션 | WorkerTopBar | 작업장 이름과 뒤로 가기만 둔다. 작업자·시연 화면의 첫 단계에서는 뒤로 가기를 두지 않는다 |
| 들림 전용 | CameraCaptureView | 아래 별도 규칙 |
| 들림 전용 | CaptureTimer | 촬영 남은 시간 표시. 촬영 중 화면 위 애니메이션은 최소화 |
| 들림 전용 | BodyMap | 통증 부위 선택. 부위마다 텍스트 라벨을 둔다. MVP는 ChoiceChipGrid로 구현한다 |
| 기본 | ChoiceChipGrid | 여러 개를 고르는 칸 없는 체크박스 목록(2열). 작업자 화면에서 줄 높이 48px. 선택 상태는 채운 네모와 체크, 굵은 글자로 표시 |
| 기본 | Icon | 선(outline) 아이콘. 선 굵기 통일, 크기 16px 또는 20px, 색은 currentColor. 장식용은 aria-hidden, 아이콘만 있는 버튼은 aria-label. 이모지를 쓰지 않는다. 콘솔에서 화면으로 가는 항목은 대상마다 다른 아이콘을 쓴다: 개선안 tool, 개선 계획 report, 보고서 초안 document, 수시 조사 survey, QR 관리 qr. 서랍을 여닫는 버튼은 menu, close |
| 기본 | IconTile | 회색 32px 타일 안의 아이콘. 공정 유형 표시와 EmptyState(옅은 타일)에 쓴다 |
| 기본 | FilterTabs | 개수가 붙은 토글 버튼. 선택된 탭도 중립색이며 브랜드 색과 위험도 색을 쓰지 않는다 |
| 기본 | SearchField | 검색 입력. 라벨을 항상 보이게 두고, 안내 문구(placeholder)는 text-secondary |
| 들림 전용 | OptimizerResultTable | 선택된 개선안, 비용, 예상 위험 감소량을 표로 표시 |
| 들림 전용 | QrEntryScreen | QR 접속 직후 첫 화면. 익명이라는 점을 먼저 안내한다 |
| 들림 전용 | QrCode | 공정 QR. text 색 칸과 surface 배경, 4칸 여백. 칸 배열은 서버에서 만들어 넘기고 QR 라이브러리를 브라우저에 싣지 않는다 |

## 카드 사용
- 카드는 공감 카드(EmpathyCard), 모달, 하단 시트에만 쓴다. 목록과 요약은 표와 구분선으로 정리한다.

## 위험한 동작
- 삭제처럼 되돌릴 수 없는 동작은 secondary 버튼으로 두고, 누르면 Modal로 결과를 설명한 뒤 한 번 더 확인받는다.
- 확인 버튼에는 동작과 대상을 함께 적는다(예: "‘보조 롤러’ 삭제").
- 같은 줄의 맨 끝에 두고, 다른 버튼과 24px 이상 떼거나 구분선으로 나눈다. 표의 행에는 두지 않는다.
- 예외: 표의 행에서는 "더보기" 메뉴의 맨 아래에 구분선(PopoverDivider)으로 떼어 둘 수 있다(개선안 삭제, QR 비활성화). 행에 바로 두지는 않는다.
- 빨간 버튼은 쓰지 않는다 (위험도 색 규칙과 충돌, docs/design-principles.md P1).
- 견적 수락은 위험한 동작이 아니라 견적 비교 화면의 주요 결정이다(아래 "버튼 위계").

## 이동
- 콘솔의 1단계 화면(개요, 공정 · 개선안, 견적 요청, 개선 계획, 수시 조사, 보고서 초안, QR 관리)은 ConsoleSidebar로 오간다. 화면 안에 "개요"로 돌아가는 버튼을 두지 않는다.
- 넓은 화면(screen-lg, 1024px 이상)에서 ConsoleSidebar는 왼쪽에 고정한다. 좁은 화면에서는 머리글의 메뉴 버튼(IconButton menu, aria-expanded, aria-controls)이 왼쪽 서랍(네이티브 dialog)을 연다. 서랍은 포커스를 가두고 Esc, 바깥 누름, 항목 선택으로 닫히며(닫기 버튼은 IconButton close), 닫히면 메뉴 버튼으로 포커스를 돌려준다.
- 지금 화면의 항목은 aria-current="page"와 왼쪽 막대, 굵은 글자로 표시한다. 색만으로 구분하지 않는다.
- 사업장 선택은 머리글의 Select 하나로 한다. 화면 폭이 screen-sm(640px) 미만이면 서랍 맨 위로 옮긴다. 고른 사업장은 모든 콘솔 이동에 ?site=로 넘긴다(docs/console-metrics.md). 화면 안에 다른 사업장으로 가는 버튼을 두지 않는다.
- 2단계 이하 화면(공정 상세, 개선안 추가·수정, 요청 상세, 저장된 계획, 수시 조사 시작)은 제목 위에 Breadcrumb로 경로 전체를 보여 준다. 예: 공정 · 개선안 › 조립 A라인 › 개선안 수정. 마지막 항목은 지금 화면이라 링크가 아니다.
- 저장·삭제 뒤에는 방금 다룬 대상이나 상위 화면으로 가고, 사업장을 유지한다. 결과는 주소에 정해진 결과 코드만 넘기고(예: ?done=saved), 도착 화면이 코드에 맞는 문구를 골라 위쪽에 한 줄 InlineAlert로 알린다. 문장을 주소에 넣지 않는다. 모르는 코드는 무시한다.
- 표의 행에서 상세로 가는 이동은 행의 이름을 링크로 둔다. 버튼을 따로 두지 않는다. 행이 갈 곳이 하나뿐인 표(공정 목록, 견적 요청 목록, 개선 계획 목록, 개요의 공정 표, 파트너 목록)는 그 링크의 누름 영역을 행 전체로 늘린다(DataTable rowLink + TextLink stretched). 행 어디를 눌러도 상세로 가고, 마우스를 올리면 행 배경이 짙어지며, 키보드는 링크 하나로 이동하고 초점은 행 전체의 focus-ring으로 보인다. 행에 onClick을 붙이지 않는다. 행 안에 동작이 여럿 있는 표에는 쓰지 않는다.
- 작업자·시연 화면(/w, /s)은 단계마다 WorkerTopBar를 둔다. 앞 단계로 갈 때마다 브라우저 기록을 하나 쌓아, 브라우저 뒤로 가기(iOS 가장자리 밀기 포함)와 TopBar 뒤로가 같이 앞 단계로 간다. 주소는 바꾸지 않고, history.state에는 단계 번호만 넣으며 토큰은 넣지 않는다(docs/auth.md). Next.js가 기록에 둔 상태는 지우지 않는다(지우면 뒤로 갈 때 페이지가 새로 고쳐진다). 기다림, 오류, 결과는 같은 기록을 바꿔 쓴다. 첫 단계, 기다리는 화면, 더 갈 곳이 없는 화면(QR 거부, 진행 사라짐, /s 결과)에는 뒤로를 두지 않는다. /s 결과에서는 토큰을 이미 썼으므로 뒤로 가도 결과에 머문다. 새로 고침이나 다시 열기로 토큰이 사라졌는데 단계 번호가 남아 있으면 "진행 내용이 사라졌어요"로 안내하고 QR을 다시 찍게 한다.
- 파트너 화면은 사이드바 없이 머리글과 Breadcrumb만 둔다.
- 머리글(콘솔은 사이드바 맨 위와 좁은 화면 머리글)의 서비스 이름은 첫 화면으로 가는 링크다(ServiceHomeLink). "들림 콘솔"은 지금 사업장의 개요(?site= 유지), "들림 파트너스"는 `/partners`로 간다. 그 화면에 있으면 aria-current="page"를 둔다. TextLink와 달리 호버 밑줄이 없는 예외이며, 키보드 포커스 표시(focus-ring)는 그대로 둔다.

## 버튼 위계
| 종류 | 쓰는 곳 | 모양 |
|---|---|---|
| 주요 | 화면의 결과물을 만드는 동작 하나. 결과가 나온 뒤에는 그 결과를 남기는 동작(예: 개선 계획 "저장")이 주요가 된다. 견적 비교 화면에서는 "선택한 견적 수락"(확인 창 유지) | Button primary. 화면당 하나 |
| 보조 | 같은 화면의 다른 동작 | Button secondary |
| 이동 | 다른 화면으로 가기 | TextLink. Button 모양으로 두지 않는다 |
| 위험 | 되돌릴 수 없는 동작(삭제, 비활성화, 초안 삭제, 수락 없이 마감) | 위 "위험한 동작"을 따른다 |

- 표의 행 동작이 3개 이상이면 자주 쓰는 하나만 행에 두고 나머지는 "더보기"(IconButton more + Popover)로 모은다. 위험 동작은 행에 바로 두지 않고 메뉴 맨 아래 구분선 뒤에 둔다(위 "위험한 동작"의 예외). 예: 개선안 표는 행에 "시연 촬영", 메뉴에 "견적 요청(요청 보기)" · 구분선 · "삭제". QR 관리는 행에 "기간 연장", 메뉴에 "재발급" · 구분선 · "비활성화".
- 화면의 주요 작업을 새로 시작하는 진입(새로 만들기)은 다른 화면으로 가더라도 주요 버튼 모양을 쓸 수 있다. 화면당 하나.
- 한 줄에 주요 버튼과 보조 버튼이 함께 있으면 주요 버튼을 맨 앞에 둔다. Modal의 버튼은 취소를 먼저 둔다.
- 작업자 첫 화면(/w)은 "자세 촬영하기"가 주요, "아픈 곳만 알리기"가 보조다. 통증 신고 완료 화면은 "들려요" 공감 카드가 중심이라 "자세 촬영하기"와 "처음으로"를 모두 보조로 둔다.

## 선택 요소
| 고르는 것 | 컴포넌트 | 규칙 |
|---|---|---|
| 하나, 바로 화면이 바뀜(사업장, 보고서에 넣을 계획) | Select(콘솔), Tabs(같은 화면의 보기 전환) | 링크 버튼 묶음으로 만들지 않는다 |
| 하나, 폼 안에서 | SegmentedControl | 선택지마다 칸(테두리, 배경)을 두지 않고 동그라미와 글자만 둔다. 줄 전체를 누를 수 있다. 선택됨은 채운 동그라미와 굵은 글자, 키보드 초점은 줄 바깥의 focus-ring이다. 비활성은 동그라미와 글자 모두 text-disabled |
| 표의 행 하나(견적 고르기) | DataTable 선택 열(radio) | 표 전체를 fieldset과 legend로 묶고, 라디오마다 행을 설명하는 접근성 이름(예: 업체 · 금액 · 기간)을 둔다. 행 어디를 눌러도 선택된다. 고를 수 없는 행(제출 상태가 아닌 견적)에는 라디오를 두지 않는다. 처음에는 아무것도 고르지 않는다 |
| 여러 개 | ChoiceChipGrid(작업자), Checkbox(콘솔) | 하나 고르기와 같은 줄 모양에 네모를 둔다. 선택 상태는 채운 네모와 체크, 굵은 글자로 보인다 |
| 긴 글(100자 넘게 받는 칸) | TextArea | 글자 수 한도를 라벨에 적는다 |
| 날짜 | DateField | 과거 날짜(발생일 등)는 max가 오늘, 미래 날짜(희망 기한 등)는 min이 오늘이다. "오늘" 표시는 실제 오늘에만 둔다 |

## 상태 표시
- 비활성 버튼 가까이에 왜 누를 수 없는지 한 줄로 적는다(예: "견적을 하나 고르면 수락할 수 있어요"). 작업자·시연 화면은 폭이 좁아 버튼 바로 위에 둔다(예: /w 첫 화면의 "아직 등록된 작업이 없어 촬영할 수 없어요.").
- 서버를 부르는 버튼은 처리 중 표시(Button loading)를 쓴다.
- 서버를 기다리는 화면 전체 상태는 ProgressIndicator와 글자를 함께 둔다. 15초가 지나면 "연결이 느려요"를 더해 보여 준다. 앞선 요청이 서버에 도착해 저장 중일 수 있으므로, 같은 요청을 다시 보내는 버튼은 저장이 두 번 되지 않는 경우에만 둔다. /w 촬영 저장은 서버가 503 unavailable로 답한 때만(저장 함수가 한 트랜잭션이라 오류면 아무것도 남지 않는다), /s는 일회용 토큰이 두 번째 저장을 막으므로 늘 둔다. 요청마다 붙이는 고유값은 docs/data-model.md "미결정"에 있다.
- 입력 칸 오류는 칸 아래, 폼 전체 오류는 제출 버튼 바로 위 InlineAlert error(role="alert")에 둔다.
- 화면 이동 뒤의 결과(저장됨, 삭제됨)는 도착 화면 위쪽 InlineAlert로 알린다(위 "이동"의 결과 코드). Toast만으로 알리지 않는다.
- 선택된 값과 지금 위치는 색만이 아니라 모양(체크, 채움, 막대, 굵기)으로도 구분한다.
- 휴대폰 화면의 예외 상태
  - 카메라 권한 거부: 기기별로 권한을 바꾸는 곳을 안내하고(iOS Safari: 주소창 aA → 웹사이트 설정 → 카메라), "다시 시도"를 둔다.
  - 카메라 사용 중: "다른 앱이 카메라를 쓰고 있어요"로 안내한다.
  - 카메라 없음: "카메라를 찾을 수 없어요"로 안내한다.
  - 그 밖의 카메라 오류: "카메라를 켜지 못했어요"로 안내하고 "다시 시도"를 둔다. 카메라 없음으로 묶지 않는다.
  - 보내기 실패: /w는 503 unavailable이면 "다시 보내기"(같은 결과)와 "다시 찍기"를, 응답이 없거나 그 밖의 응답이면 저장됐는지 알 수 없다고 적고 "다시 찍기"만 둔다. /s는 "다시 보내기"와 "다시 찍기"를 두고, 응답 없이 끊긴 뒤 다시 보내기가 401을 받으면 "이미 저장되었을 수 있어요. 콘솔에서 확인해 주세요."로 안내한다. "다시 보내기"가 있는 화면에는 새로 고치면 결과가 사라진다고 적는다.
  - 저장 한도(429)와 품질 미달(422)은 결과나 재촬영 안내를 보여 준다.

## CameraCaptureView 규칙
- 영상은 video 요소, 관절 점은 그 위의 canvas에 그린다.
- MediaPipe에 넣는 영상은 좌우반전하지 않는다. 거울 모드에서는 video와 canvas를 함께 뒤집는다.
- 가시성 기준 미만인 점은 무효로 처리하고, 무효 점이 포함된 각도는 표시하지 않는다.
- 카메라 권한 거부, 카메라 없음, 분석 실패 상태를 각각 정의한다.
- 촬영 중에는 transform과 opacity 외의 애니메이션을 쓰지 않는다.
